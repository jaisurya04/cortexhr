# Phase 2 implementation guide

This extends the existing Phase 1 repository without replacing its six existing notebooks. Phase 2 work is grouped under `05_Starter/notebooks/phase2/` so Phase 1 artifacts remain intact.

## New work
- `src/cortexhr/phase2/payroll.py`: audit, leakage-aware ratio features, transparent rules, Isolation Forest and scoring.
- `src/cortexhr/phase2/chatbot.py`: TF-IDF + Logistic Regression, held-out evaluation, FAQ response mapping, session slots, confidence fallback and salary privacy override.
- `05_Starter/api_skeleton/app/main.py`: `/v1/health`, `/v1/anomaly/attendance`, `/v1/anomaly/payroll`, `/v1/chat`.
- `tests_phase2/test_phase2.py`: feature, detector, chatbot, API and validation checks.
- Nine workflow notebooks cover audit, EDA/features, rules/baselines, frozen scoring, CX-06 evaluation, explanations, API checks, NLU and dialogue/permissions/UI.

## Setup and run

```bash
pip install -r 05_Starter/requirements.txt
pytest -q tests_phase2
uvicorn app.main:app --app-dir 05_Starter/api_skeleton --reload
```

Open `http://127.0.0.1:8000/docs` for API testing.

## Important validation caveat

CX-06 was evaluated by the project owner with the authorised label file (not included in this package, never committed) against the frozen predictions: see `reports/phase2/payroll_cx06_per_type.csv` and `docs/PHASE2_STATUS_REVIEW.md`. Overall: precision 0.316, recall 0.95 (rules alone: precision 0.860, recall 0.92). The label file itself could not be inspected by the package author; the table is internally consistent (tp + fn = support, 95 tp / 301 flagged).

## Notebook conventions

Run notebooks from the repository root or adjust `ROOT` resolution if your environment launches Jupyter from another directory. Run in order 07–15. The detector predictions are saved before any validation labels are opened. Outputs under `reports/phase2/` are generated by executing the notebooks; the report template intentionally asks you to record real metrics after execution.

## Chatbot NLU improvement update (2026-10-26)

- Added `05_Starter/notebooks/phase2/16_chatbot_advanced_model_improvement.ipynb` for data quality/leakage checks, 5-fold stratified cross-validation, model comparison, per-intent metrics, confusion/error analysis, and held-out reporting.
- Updated the production intent pipeline to combine word-level TF-IDF (1–2 grams) and character-boundary TF-IDF (2–5 grams) with Logistic Regression. The combined representation can better handle short messages and some spelling variations; it is not a guarantee of 90%+ performance.
- The official data contains 858 training messages across 33 intents and 132 held-out examples (4 per intent). The current production-compatible model obtains **81.06% held-out accuracy (107/132 correct)** on the supplied test set. This is higher than the previous 75.76% baseline, but remains below 90%; do not claim otherwise.
- The advanced notebook chooses among probability-producing candidates by training-only cross-validation, because runtime safe-fallback logic requires `predict_proba`. The held-out set is reported separately and must not be used for repeated tuning.
- The provided test set is small and synthetic; results may not represent real employee queries. A future independent test set and carefully reviewed additional training examples are recommended before any claim of production-grade accuracy.
- Re-run `pytest -q tests_phase2/test_phase2.py` after changes. Notebook outputs are saved as evidence, but always re-run them in the target environment before submission.
